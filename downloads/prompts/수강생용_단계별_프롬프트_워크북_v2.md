# AI 강의 제작소 수강생용 단계별 프롬프트 워크북 v2

이 워크북은 강의계획서, `design.md`, 샘플 PPT를 가진 강사가 에이전트AI와 수업을 기획한 뒤 `$lesson-deck-builder`로 HTML 또는 PPTX 교안을 제작할 때 사용한다.

AI는 자료 분석, 누락·충돌 발견, 대안 제시, 조사 보조, 구조 초안을 맡는다. 수업 방향, 목표와 범위, 시간 배분, 자료 채택, 디자인 우선순위, 파일 제작과 공개 여부는 사용자가 결정한다. 제작 스킬은 사용자가 승인한 내용을 파일로 구현하고 실제 화면을 검수한다.

## 전체 진행 순서

```text
0 시작 확인
→ 1 자료 분석
→ 2 수업 방향 비교와 선택
→ 3 더 필요한 자료 확인과 조사
→ 4 수업 순서와 목차
→ 5 장표별 제작 안내표
→ 6 최종 제작 요청
→ 7 제작 스킬로 대표 장표 2장
→ 8 자가 점검과 AI 검토
→ 9 사용자 선택 반영과 전체 확장
→ 10 활동자료 제작
→ 11 홈페이지 제작 준비
```

목차만 만든 뒤 바로 제작하지 않는다. **각 장표에 무엇을 넣을지 사람이 확인한 뒤** 제작 스킬을 호출한다.

## 사용하는 방법

새 에이전트 작업에서는 다음 순서로 붙여넣는다.

1. 프로젝트 카드
2. 공통 실행 규약
3. 프롬프트 0

같은 대화에서는 AI가 현재 단계와 다음 단계를 기록하게 하고 필요한 단계 프롬프트만 이어서 사용한다. 새 작업에서 재개할 때는 `프롬프트 12 — 작업 이어받기`를 사용한다.

진행 방식은 둘 중 하나를 고른다.

- `결과가 달라지는 결정에서만 멈춤`: 프롬프트 1~5의 제안을 연속 작성하고, 실제 제작 전에 결정 항목을 한 번에 받는다.
- `단계마다 확인`: 각 단계 결과를 사용자가 확인한 다음 넘어간다.

어느 방식을 선택해도 외부 조사, 실제 파일 제작, 전체 교안 확장, 외부 공개는 해당 작업의 사용자 확인 없이 실행하지 않는다.

## 프로젝트 카드

모르는 값은 `미정`으로 둔다. 미정은 AI가 임의로 확정하라는 뜻이 아니다.

```text
[내 수업]
과정명: [내 수업 이름 / 미정]
학습자: [학교급·학년·대상·수준 / 미정]
수업 시간 또는 차시: [사용자가 정한 값 / 미정]
이번 작업 범위: [예: 장표별 제작 안내표까지 / 대표 장표 2장까지]
진행 방식: [결과가 달라지는 결정에서만 멈춤 / 단계마다 확인]

[준비물]
강의계획서 또는 교안 원고: [첨부·실제 경로·붙여넣기]
디자인 기준 파일: [첨부·실제 경로·붙여넣기]
샘플 PPT 또는 대표 화면 이미지: [첨부·실제 경로]
추가 자료: [첨부·경로·링크·붙여넣기 / 없음]

[이미 정한 것]
반드시 유지할 내용: [내용 / 미정]
바꿔도 되는 내용: [내용 / 미정]
피하고 싶은 것: [내용 / 미정]
원하는 수업 방향: [미정이어도 됨]

[파일과 권한]
결과 형식: [16:9 HTML / 편집 가능한 PPTX / 둘 다 / 미정]
결과 저장 위치: [사용자 지정 / 미정]
결과 파일 이름: [사용자 지정 / 미정]
기존 파일 수정 허용 범위: [대상 / 허용하지 않음]
외부 자료 검색: [허용 / 항목별 확인 후 허용 / 허용하지 않음]
외부 공개·업로드: [허용 / 확인 후 허용 / 포함하지 않음]
진행 기록: [사용자가 지정한 파일 / 채팅에만 기록]
```

## 공통 실행 규약

```text
[목적]
제공된 자료를 실제로 확인하고, 사용자가 결정해야 할 것과 AI가 실행할 일을 구분하면서 수업 기획과 교안 제작을 단계적으로 진행한다.

[자료 확인]
- 파일명만 보고 내용을 추정하지 않는다.
- 문서는 본문·표·페이지, 마크다운은 제목과 규칙, PPT는 장표 수·비율·대표 화면을 실제로 확인한다.
- 화면을 보지 못했으면 `텍스트만 확인`, 실제 내용을 열지 못했으면 `미확인`으로 표시한다.
- 강의계획서는 수업 내용, design.md는 시각 규칙, 샘플 PPT는 레이아웃과 현장 가독성의 참고로 구분한다.
- 샘플 PPT의 교육 내용과 강사 시연 주제를 참가자의 수업 내용에 복사하지 않는다.

[사용자 결정]
- AI는 근거, 누락, 충돌, 예상 영향, 대안을 제시한다.
- 교육적 적합성, 수업 방향, 목표·범위, 학교급별 시간, 자료 채택, 장표 구성, 디자인 충돌, 결과 형식과 제작 진행은 사용자가 결정한다.
- 사용자가 확정하지 않은 항목을 `확정`으로 표시하지 않는다.
- 입력된 시간과 필수 내용이 충돌하면 삭제하지 말고 차시 분리·활동 조정 등의 대안과 영향을 보여준다.

[작업 권한]
- 입력 자료는 읽고 분석할 수 있다.
- 외부 검색, 유료 기능, 업로드, 공개, 삭제는 프로젝트 카드의 허용 범위 안에서만 한다.
- 파일은 사용자가 지정한 위치와 이름으로만 만든다.
- 이름이 미정이면 이해하기 쉬운 한글 이름을 2~3개 제안하고 채팅에 먼저 보여준다.
- 같은 이름의 파일을 임의로 덮어쓰지 않는다.

[에이전트 실행]
- 확정된 단계 안에서는 자료 읽기, 초안 작성, 구현, 오류 수정, 재검증을 이어간다.
- 결과가 달라지는 결정, 외부 조사, 실제 제작, 전체 확장, 공개 앞에서는 필요한 사용자 결정을 분명히 표시한다.
- 오류가 나면 안전한 대안을 최대 2회 시도하고, 실패하면 부분 결과를 보존한 채 원인과 필요한 입력을 보고한다.
- 만들지 않은 파일을 `제작 완료`, 최신 저장본을 열거나 렌더링하지 않은 결과를 `검증 완료`라고 말하지 않는다.

[결과 표시 순서]
1. 한눈에 보기
2. 핵심 결과와 근거
3. 사용자가 결정할 것
4. 만든 파일과 검증 상태
5. 현재 상태
6. 다음 단계와 필요한 입력

[진행 기록]
각 단계 끝에 현재 단계, 확인한 입력, 사용자 확정 사항, 제안 상태인 항목, 실제 파일, 검증 결과, 남은 결정, 다음 프롬프트를 기록한다. 새 작업에서 재개할 때는 기록과 실제 파일을 먼저 대조한다.
```

## 프롬프트 0 — 작업 환경과 준비물 확인

사용 시점: 새 에이전트 작업을 시작할 때.

```text
[목적]
프로젝트 카드의 자료와 권한을 확인하고 지금 시작할 수 있는 범위를 정리한다.

[해야 할 일]
1. 실제로 보이는 첨부와 경로를 확인한다.
2. 파일 읽기, DOCX 확인, PPT 렌더링, HTML 브라우저 확인, 파일 생성·수정 기능 중 실제 가능한 것을 구분한다.
3. 진행 기록이 있으면 실제 결과물과 대조해 완료·미완료 단계를 복원한다.
4. 강의계획서, design.md, 샘플 PPT가 각각 있는지 확인한다.
5. 바로 할 수 있는 일과 사용자 결정 전에는 할 수 없는 일을 나눈다.

[출력]
- 시작 가능 여부와 가장 큰 제한
- 기능 확인: 작업 | 가능 여부 | 확인 근거 | 대안
- 준비물 목록: 자료 | 발견 여부 | 열기 전 상태
- 권한 범위: 읽기 | 만들기 | 수정 | 검색 | 공개
- 현재 상태와 다음 단계

[중단]
필수 자료의 위치를 찾을 수 없으면 필요한 자료 한 가지만 구체적으로 질문한다. 자료를 찾았으면 프롬프트 1로 이어간다.
```

## 프롬프트 1 — 세 자료 분석과 수업 현황 파악

사용 시점: 준비물 3종을 찾은 뒤.

```text
[목적]
강의계획서, design.md, 샘플 PPT를 실제로 읽고 각 자료가 제공하는 내용과 제작 전에 확인할 문제를 사람이 빠르게 파악하게 한다.

[해야 할 일]
1. 강의계획서에서 학습자, 핵심 질문, 목표, 내용, 활동, 결과물, 평가 증거, 차시를 추출한다.
2. 목표·활동·평가가 어떻게 연결되는지 표시하되 적절성의 최종 판정은 하지 않는다.
3. design.md에서 색, 글자, 여백, 형태, 이미지, 모션, 접근성, 금지 규칙을 추출한다.
4. 샘플 PPT의 장표 수와 비율을 확인하고 대표 화면에서 제목·본문 위계, 정보량, 여백, 반복 배치, 도형 비중을 관찰한다.
5. 누락, 모순, 애매한 표현, 최신성·출처 확인이 필요한 내용을 `확인 필요`로 표시한다.
6. 세 자료의 역할을 섞지 않는다.

[출력]
- 한눈에 보는 수업 현황
- 자료 역할 지도: 자료 | 실제 확인 범위 | 제공하는 것 | 제공하지 않는 것 | 근거
- 수업 구조: 목표 | 활동 | 결과물·평가 증거 | 연결 상태
- 디자인 핵심과 샘플 화면 관찰
- 누락·충돌·확인 필요 항목
- 사용자가 결정할 것
- 현재 상태와 다음 단계: `수업 방향 비교`

[중단]
핵심 자료를 실제로 읽을 수 없으면 다음 단계로 넘어가지 않는다. 진행 방식이 `단계마다 확인`이면 여기서 멈춘다.
```

## 프롬프트 2 — 수업 방향 비교와 사람의 선택

사용 시점: 수업 현황을 확인한 뒤.

```text
[목적]
현재 계획서로 가능한 수업 방향을 비교해 사용자가 주 방향과 보조 방향을 선택할 수 있게 한다.

[방향 후보]
이론·개념 이해, 사례·스토리, 질문·토론, 실습·도구 사용, 게이미피케이션, 프로젝트·결과물 제작 중 자료에 맞는 후보만 사용한다. 필요하면 다른 방향을 추가한다.

[해야 할 일]
1. 현재 계획서에서 이미 강하게 드러나는 방식과 약하게 드러나는 방식을 근거와 함께 찾는다.
2. 실행 가능한 방향안 2~3개를 만든다. 한 방향을 정답처럼 확정하지 않는다.
3. 각 안에서 학습자가 주로 하는 행동, 교안 리듬, 필요한 화면, 기대 효과, 주의점, 계획서에서 유지·조정될 부분을 비교한다.
4. 혼합안이라면 주 방향과 보조 방향, 적용 구간을 구분한다.
5. 추천이 있다면 추천 이유와 맞지 않을 수 있는 조건까지 적는다.

[출력]
- 현재 수업에서 보이는 방향
- 방향 비교표: 안 | 주·보조 방향 | 학습자 행동 | 교안 특징 | 기대 효과 | 주의점 | 계획서 영향
- AI의 추천과 조건
- 사용자가 복사해 답할 `방향 선택 카드`
  - 주 방향:
  - 보조 방향:
  - 반드시 유지할 활동:
  - 줄이거나 제외할 활동:
  - 아직 결정하지 못한 것:
- 현재 상태와 다음 단계: `더 필요한 자료 확인`

[중단]
AI는 방향을 확정하지 않는다. `단계마다 확인`이면 사용자의 선택을 기다린다. 연속 진행 방식이면 각 안을 제안 상태로 유지한다.
```

## 프롬프트 3 — 더 필요한 자료 확인과 조사

사용 시점: 수업 방향 후보 또는 사용자의 선택이 나온 뒤.

```text
[목적]
수업 제작에 실제로 필요한 자료만 찾도록 조사 범위와 채택 기준을 정한다.

[해야 할 일]
1. 목표, 활동, 사례, 평가, 시각자료별로 현재 자료만으로 가능한 것과 자료가 비는 부분을 구분한다.
2. 공백마다 왜 필요한지, 어느 장면에서 쓸지, 없으면 어떤 대안이 있는지 적는다.
3. 최신 통계·정책·뉴스·정치 관련 사실, 이미지·영상·폰트의 사용 조건은 검증 필요로 표시한다.
4. 외부 검색 권한이 없으면 검색하지 않고 조사 계획만 제시한다.
5. 검색이 허용되면 신뢰할 수 있는 원자료와 공식 출처를 우선해 조사하고, 출처명·링크·발행/갱신 시점·확인일·사용 위치를 남긴다.
6. 찾지 못한 값이나 상충하는 자료를 지어내지 않는다.
7. AI는 후보를 정리하고 사용자는 채택·보류·제외를 결정한다.

[출력]
- 더 필요한 자료 한눈에 보기
- 조사 필요표: 필요한 자료 | 필요한 이유 | 사용할 장면 | 검색어·후보 출처 | 없을 때 대안 | 검색 권한
- 검색을 실행했다면 자료 후보표: 자료 | 핵심 내용 | 출처·시점 | 사용할 위치 | 주의점 | 사용자 채택
- 사용자가 복사해 답할 `자료 선택 카드`
- 현재 상태와 다음 단계: `수업 순서와 목차`

[중단]
외부 검색 또는 자료 채택이 다음 결과를 크게 바꾸면 사용자 확인을 기다린다. 자료가 없어도 구조를 만들 수 있으면 해당 위치를 `자료 확정 후 삽입`으로 남길 수 있다.
```

## 프롬프트 4 — 수업 순서와 목차 만들기

사용 시점: 수업 방향과 사용할 자료 범위를 확인한 뒤.

```text
[목적]
선택한 수업 방향을 학습자가 실제로 따라갈 순서로 바꾸고, 사람이 비교할 수 있는 수업 흐름과 목차를 만든다.

[해야 할 일]
1. 계획서의 목표·활동·평가 증거를 누락하지 않는다.
2. 구조안 2~3개를 제안하고 각 안에서 학습자 경험, 강사의 설명량, 활동 비중, 장점을 비교한다.
3. 선택한 방향이 도입, 개념·사례, 시범, 활동, 자가 점검, 정리에서 어떻게 드러나는지 표시한다.
4. 장표 수는 내용의 난도, 설명 밀도, 학습자 행동, 시연 필요에 따라 범위로 제안한다.
5. 시간은 사용자가 입력한 경우에만 운영 검토안으로 제시한다. 필수 내용을 임의로 삭제하거나 분 단위 일정을 확정하지 않는다.
6. 조사 중인 자료 위치는 명확한 자리표시자로 남긴다.

[출력]
- 구조안 비교: 안 | 흐름 | 학습자 경험 | 강사 역할 | 장표 범위 | 장점 | 주의점
- AI의 추천과 조건
- 선택안의 교안 목차: 구간 | 목적 | 핵심 내용 | 학습자 행동 | 연결 목표 | 필요한 자료
- 사용자가 복사해 답할 `구조 선택 카드`
- 현재 상태와 다음 단계: `장표별 제작 안내표`

[중단]
AI는 구조와 장표 범위를 확정하지 않는다. `단계마다 확인`이면 사용자의 선택을 기다린다. 연속 진행이면 가장 근거가 분명한 안을 `가안`으로 사용하되 제작하지 않는다.
```

## 프롬프트 5 — 장표별 제작 안내표 만들기

사용 시점: 사용할 수업 순서가 정해진 뒤.

```text
[목적]
선택한 목차를 제작 스킬이 다시 추측하지 않도록, 각 장표에 넣을 내용을 구체적으로 적는다.

[해야 할 일]
1. 각 장표에 학습 흐름상 목적과 핵심 메시지 하나를 배정한다.
2. 화면에 보일 문구와 발표자용 설명을 분리한다.
3. 화면 유형은 표지, 질문, 개념, 비교, 사례, 절차, 시범, 활동, 자가 점검, 정리 등 실제 기능으로 적는다.
4. 활동 장표에는 학습자가 할 일, 사용할 자료, 완료 모습, 막혔을 때의 대안을 포함한다.
5. 이미지·영상·통계·인용은 출처와 사용할 위치를 적고, 미확정이면 자리표시자를 쓴다.
6. 한 화면에 정보가 과하면 몰래 줄이지 말고 분할안과 영향을 제안한다.
7. 샘플 PPT의 교육 내용은 넣지 않는다.

[출력]
- 장표 수와 구간 한눈에 보기
- 장표별 제작 안내표:
  번호 | 제목 | 장표 목적 | 핵심 메시지 | 화면 문구 | 화면 유형 | 시각자료·출처 | 학습자 행동 | 발표 노트 | 이전·다음 연결 | 상태
- 분할·통합이 필요한 장표와 이유
- 미확정 자료와 제작 전 결정
- 사용자가 복사해 답할 `장표 안내 확인 카드`
  - 그대로 승인:
  - 수정 후 승인:
  - 보류:
  - 제작에서 반드시 유지:
- 현재 상태와 다음 단계: `최종 제작 요청`

[중단]
장표별 제작 안내를 사용자가 확인하기 전에는 HTML/PPTX 코드를 만들거나 제작 스킬을 실행하지 않는다.
```

## 프롬프트 6 — 최종 제작 요청문 만들기

사용 시점: 장표별 제작 안내표를 사용자가 확인한 뒤.

```text
[목적]
승인된 기획을 `$lesson-deck-builder`가 바로 제작할 수 있는 입력 묶음과 호출문으로 정리한다.

[해야 할 일]
1. 확인한 장표별 제작 안내표, 원본 계획서, design.md, 샘플 PPT, 채택 자료의 실제 위치를 확인한다.
2. design.md와 샘플 PPT의 전체 분위기, 색·배경, 글자, 레이아웃, 형태·그림자, 이미지·아이콘, 모션이 다르면 요소별 차이와 결과를 보여준다.
3. 둘 중 하나만 선택하게 하지 않는다. `샘플 스타일 유지 + 디자인 파일 색감 적용`처럼 요소마다 어느 자료를 따를지 사용자가 선택하게 한다.
4. 사용할 폰트의 파일·설치 여부, HTML/PPTX 포함 가능성, 배포 권리, 대체 글꼴과 재검수 방법을 확인한다.
5. 결과 형식, 대표 장표 범위, 저장 위치, 파일명, 새 파일/수정 파일을 확인한다.
6. 제작 스킬이 설치되어 있는지 확인한다. 없으면 실행한 척하지 말고 설치 안내 또는 `SKILL.md`를 제공해야 한다고 표시한다.

[출력]
- 제작 준비 상태: 바로 제작 / 결정 후 제작 / 자료 필요
- 입력 확인표
- 디자인 요소별 적용표: 요소 | design.md에서 가져올 것 | 샘플 PPT에서 가져올 것 | 사용자 선택
- 폰트 확인표: 제목·본문 글꼴 | 실제 파일·설치 | 사용·배포 가능 | 대체 글꼴 | 재검수
- 사용자가 복사해 답할 `제작 결정 카드`
  - 결과 형식:
  - 이번 제작 범위:
  - 전체 분위기:
  - 색·배경 출처:
  - 글자·폰트 출처:
  - 레이아웃 출처:
  - 형태·그림자 출처:
  - 이미지·아이콘 출처:
  - 모션 출처:
  - 제목·본문 글꼴과 파일:
  - 대체 글꼴:
  - 반드시 유지할 요소:
  - 저장 위치:
  - 파일명:
  - 새 파일/수정 파일:
- 결정 카드가 채워졌을 때 사용할 `$lesson-deck-builder` 호출문
- 현재 상태와 다음 단계: `대표 장표 2장 제작`

[중단]
결과 형식, 범위, 디자인 우선순위, 저장 위치와 이름이 확정되지 않았으면 제작하지 않는다.
```

## 프롬프트 7 — 제작 스킬로 대표 장표 2장 만들기

사용 시점: 제작 결정 카드가 확정된 뒤. Codex에서는 `$lesson-deck-builder`를 함께 호출한다.

```text
$lesson-deck-builder

[목적]
확인한 장표별 제작 안내표와 제작 결정 카드에 따라 학습 기능이 다른 대표 장표 2장을 실제 HTML 또는 PPTX로 만들고 최신 저장본을 검증한다.

[입력]
- 확인한 장표별 제작 안내표: [첨부·경로·붙여넣기]
- 원본 강의계획서 또는 교안 원고: [첨부·경로]
- design.md: [첨부·경로]
- 샘플 PPT: [첨부·경로]
- 채택 자료: [첨부·경로·링크 / 없음]
- 사용자가 확정한 제작 결정 카드: [내용]

[해야 할 일]
1. 입력과 제작 범위를 짧게 대조한다.
2. 제작을 막는 정보가 있을 때만 질문한다.
3. 설명·개념형 1장과 활동·비교·절차형 1장처럼 기능이 다른 장표를 고른다.
4. 승인된 내용은 다시 교육적으로 판단하거나 임의 삭제하지 않는다.
5. 실제 파일을 만들고 렌더링 또는 브라우저 화면에서 잘림, 겹침, 위계, 대비, 정보량을 확인한다.
6. 오류는 해당 요소만 수정하고 최신 파일을 다시 확인한다.
7. 전체 교안이나 홈페이지로 범위를 넓히지 않는다.

[결과]
- 만든 대표 장표와 선택 이유
- 실제 파일 위치
- 검증표: 조건 | 확인 방법 | 결과 | 수정 내용 | 남은 제한
- 사용자가 화면에서 볼 항목: 장표당 최대 3개
- 현재 상태: 사용자 결정 대기
```

스킬 호출 문법을 지원하지 않는 환경에서는 배포받은 `lesson-deck-builder/SKILL.md`를 AI가 읽을 수 있게 제공한다. 제작 기능이 없는 대화형 AI에서는 프롬프트 7을 실행 완료로 처리하지 않는다.

## 프롬프트 8 — 자가 점검과 AI 검토

사용 시점: 사용자가 대표 장표를 직접 본 뒤.

```text
[목적]
사용자의 관찰과 AI가 실제 화면에서 찾은 문제를 구분하고, 사용자가 유지·수정·보류를 결정할 근거를 만든다.

[입력]
- 검토할 최신 파일: [첨부·실제 경로]
- 사용자가 본 환경: [노트북 / 프로젝터 / 모바일 / 기타]
- 사용자의 관찰: [잘 보인 점 / 불편한 점 / 미확인]
- 반드시 유지할 부분: [내용]

[해야 할 일]
1. 최신 저장 파일과 실제 렌더 화면을 확인한다.
2. 사용자가 말한 문제와 AI가 새로 발견한 문제를 구분한다.
3. 문제마다 위치, 관찰 근거, 최소 수정안, 다른 대안, 수정 영향을 제시한다.
4. 취향 차이와 가독성·학습 사용 문제를 구분한다.
5. AI가 유지·수정·보류를 대신 선택하지 않는다.
6. 이 단계에서는 파일을 수정하지 않는다.

[출력]
- 유지할 강점과 우선 확인 문제
- 검토표: 우선순위 | 장표·위치 | 관찰 | 근거 | 수정 대안과 영향 | 사용자 결정
- 확인하지 못한 것
- 사용자가 복사해 답할 `수정 결정 카드`: 유지 | 수정 | 보류
- 현재 상태: 사용자 결정 대기
- 다음 단계: `선택 반영과 전체 확장`
```

## 프롬프트 9 — 사용자 선택 반영과 전체 교안 확장

사용 시점: 대표 장표의 수정 결정 카드와 전체 확장 여부가 확정된 뒤. 제작에는 `$lesson-deck-builder`를 사용한다.

```text
$lesson-deck-builder

[목적]
사용자가 수정으로 선택한 항목을 대표 장표에 반영하고, 승인된 디자인 규칙으로 지정한 범위의 전체 교안을 완성한다.

[입력]
- 대표 장표 최신 파일: [경로]
- 수정 결정 카드: [내용]
- 확인한 장표별 제작 안내표: [경로·붙여넣기]
- 전체 제작 범위: [사용자 확정]
- 완성본 저장 위치와 이름: [사용자 지정]

[해야 할 일]
1. 유지·수정·보류 항목을 대조하고 수정 대상으로 고른 부분만 먼저 고친다.
2. 대표 장표를 같은 조건에서 다시 검증한다.
3. 사용자가 전체 확장을 승인한 범위만 제작한다.
4. 검증된 글자, 간격, 색, 화면 패턴을 유지하되 장표 기능에 맞게 레이아웃을 바꾼다.
5. 전체를 배치 단위로 만들고 최신 저장본의 모든 장표를 확인한다.
6. 오류는 전체 재생성보다 해당 장표만 수정한다.

[결과]
- 수정·유지·보류 내용
- 완성 파일과 실제 범위
- 전체 장표 검증 결과
- 미검증 항목과 사용에 영향을 주는 제한
- 활동자료 제작에 넘길 목표·활동·용어·출처
```

## 프롬프트 10 — 활동자료와 강사자료 만들기

사용 시점: 교안의 목표·용어·활동 순서가 안정된 뒤. 이 단계는 `$lesson-deck-builder`의 범위가 아니다.

```text
[목적]
완성된 교안과 같은 목표, 용어, 활동 순서를 사용하는 수업 운영자료를 만든다.

[입력]
- 수업계획서와 확인한 장표별 제작 안내표
- 완성 교안
- 필요한 자료 종류: [활동지 / 실습 파일 / 강사 진행 노트 / 자가 점검표 / 기타]

[해야 할 일]
1. 자료마다 언제, 누가, 무엇을 위해 사용하는지 적는다.
2. 활동 지시, 필요한 입력, 완료 모습, 막혔을 때 대안을 교안과 일치시킨다.
3. 강사용 정답·내부 메모와 학습자 공개 자료를 구분한다.
4. AI는 누락과 충돌, 대안을 제시하고 사용 적합성은 사용자가 결정한다.
5. 사용자가 저장 위치와 이름을 정한 자료만 파일로 만든다.

[출력]
- 필요한 자료 목록과 교안 연결 위치
- 자료별 내용 초안
- 사용자 결정 항목
- 만든 파일과 검증 상태
- 홈페이지에 공개할 자료와 비공개 자료 구분
```

## 프롬프트 11 — 홈페이지 제작 준비

사용 시점: 교안과 활동자료가 확정된 뒤. 현재 `$lesson-deck-builder`로 실행하지 않는다.

```text
[목적]
수업 전·중·후에 사용할 홈페이지에 어떤 자료를 어떤 공개 범위로 배치할지 정리하고 사이트 제작에 바로 쓸 요청문을 만든다.

[해야 할 일]
1. 과정 소개, 커리큘럼, 교안 보기·다운로드, 활동자료, 영상·외부 링크, 출처·문의 정보를 분류한다.
2. 강사용 자료, 개인정보, API 키, 저작권이 불명확한 원본, 전체 대화 기록은 기본 비공개로 둔다.
3. PC와 모바일에서 필요한 행동과 다운로드 흐름을 정리한다.
4. 로그인, 결제, 데이터베이스, LMS 기능은 사용자가 요청하지 않으면 포함하지 않는다.
5. 공개와 업로드는 사용자가 최종 확인한 뒤 진행한다.

[출력]
- 홈페이지 구조: 페이지·구간 | 목적 | 연결 자료 | 공개 범위 | 사용자 행동
- 업로드 준비 파일 목록
- 출처·저작권·개인정보 확인 목록
- 사이트 제작에 넘길 결정 카드
- 아직 만들지 않은 항목과 다음 단계
```

## 프롬프트 12 — 새 작업에서 이어받기

```text
[목적]
진행 기록과 실제 결과물을 대조해 완료한 작업을 반복하지 않고 다음 미완료 단계부터 이어간다.

[입력]
- 프로젝트 카드
- 진행 기록 또는 이전 대화의 상태표: [첨부·경로·붙여넣기]
- 지금까지 만든 결과물: [첨부·경로]
- 이번에 이어갈 범위: [내용]

[해야 할 일]
1. 기록과 실제 파일이 일치하는지 확인한다.
2. 파일이 없거나 열리지 않으면 완료 상태를 취소하고 이유를 적는다.
3. 사용자 확정 사항, 제안 상태, 검증 결과, 남은 결정을 복원한다.
4. 다시 해야 할 일과 이어서 할 일을 구분한다.
5. 파일명 충돌과 수정 권한을 확인한 뒤 다음 미완료 단계만 실행한다.

[출력]
- 마지막 완료 단계와 실제 파일
- 그대로 유지할 사용자 결정
- 다시 확인할 것
- 지금 실행할 다음 프롬프트
- 현재 상태

[중단]
기록과 실제 파일이 크게 다르면 한쪽을 임의로 정답으로 고르지 않고 복구 선택지를 보여준다.
```

## 1차시가 끝났을 때 확인할 것

1차시의 목표는 전체 교안 완성을 강제하는 것이 아니다. 다음 결과가 있으면 제작을 이어갈 수 있다.

- 준비물 3종의 실제 확인 근거
- 현재 수업계획서의 구조와 확인할 문제
- 사람이 선택한 주·보조 수업 방향
- 추가 조사가 필요한 자료와 채택 기록
- 사람이 확인한 교안 목차와 장표별 제작 안내표
- 결과 형식과 디자인 우선순위가 담긴 제작 결정 카드
- 가능하면 실제 파일로 만들고 검증한 대표 장표 2장
- 다음 작업에서 이어갈 상태표

## 일반 대화형 AI에서 사용할 때

파일 접근이나 제작 기능이 없는 AI는 프롬프트 1~6의 기획을 도울 수 있다. 문서 본문은 붙여넣고 샘플 PPT는 대표 화면 캡처를 제공한다. 실제 파일 생성, 렌더링, 브라우저 확인을 하지 못하면 프롬프트 7~9를 완료한 것으로 표시하지 않는다.
