# Lesson Deck Builder

수업계획안이나 교안 원고를 발표 가능한 PPTX 또는 HTML 교안으로 구현한다. 장표 구성이 없으면 해당 AI의 일반 추론으로 제작용 장표 초안을 만들 수 있지만, 수업 내용의 교육적 적합성을 평가하거나 학습목표·평가를 새로 설계하는 방법은 이 스킬에서 지시하지 않는다. 제공된 내용과 사용자 결정을 보존하면서 디자인 적용, 레이아웃 구현, 파일 생성, 화면 검수에 집중한다.

## 필요한 입력

- 수업계획안, 교안 원고, 장표별 제작 안내표 중 사용할 수 있는 자료
- `DESIGN.md` 또는 `design.md`
- 샘플 PPT/PPTX 또는 대표 화면 이미지
- 결과 형식: 편집 가능한 PPTX 또는 HTML 교안
- 제작 범위, 저장 위치, 파일명

입력이 부족하면 다음만 묻는다.

- 어떤 형식과 범위를 만들 것인가
- 디자인 파일과 샘플 PPT에서 색, 글자, 레이아웃, 형태, 그림자, 이미지, 모션 중 무엇을 각각 가져올 것인가
- 어떤 파일을 새로 만들고 어떤 파일을 수정할 수 있는가

두 디자인이 다르다는 이유로 전체 자료 중 하나만 고르게 하지 않는다. 사용자는 샘플 PPT의 스타일·레이아웃·공간감은 유지하면서 디자인 파일의 색감·폰트만 적용하려 할 수 있다. 제작 전에 요소별 출처를 짧은 표로 되묻고, 사용자가 전체 우선순위를 이미 분명히 정했다면 다시 묻지 않는다.

폰트는 이름만 확인하지 않는다. 제공 파일 또는 설치 여부, HTML 웹폰트·PPTX 포함 가능 여부, 배포 권리, 대체 글꼴과 대체 후 줄바꿈 재검수 방법을 확인한다. 사용자가 폰트를 제공하지 않았다면 임의의 유료·전용 글꼴을 사용하지 않는다.

학습목표, 내용 범위, 차시 시간, 평가 방식이 적절한지는 스킬 규칙으로 판단하지 않는다. 장표 구성이 없으면 해당 AI가 제공 자료를 바탕으로 `제작용 장표 초안`을 만들고, 원문에서 유지한 것과 배치를 위해 나눈 것을 표시한 뒤 사용자 확인을 받는다. 내용이 실제로 비어 있으면 만들어내지 않고 필요한 원고를 요청한다.

## 입력 자료의 역할

충돌이 없을 때 다음처럼 사용한다.

1. 사용자의 이번 지시: 결과 형식, 범위, 수정 권한
2. 수업계획안·교안 원고·장표별 제작 안내표: 화면에 들어갈 내용과 순서의 근거
3. 디자인 파일: 색, 글자, 여백, 형태, 이미지, 모션 규칙
4. 샘플 PPT: 화면 비율, 글자 크기 관계, 정보량, 배치 유형, 현장 가독성
5. 이 스킬의 제작·검수 원칙

디자인 파일과 샘플 PPT의 색·형태·밀도가 다르면 임의로 섞지 않는다. 차이와 결과를 짧게 보여주고 색·글자·레이아웃·형태·그림자·이미지·모션별로 어느 자료를 따를지 사용자가 고르게 한다. `샘플 스타일 유지 + 디자인 파일 색감 적용`처럼 의도적인 조합도 하나의 정상 선택으로 다룬다. 샘플 PPT의 교육 내용은 복사하지 않는다.

디자인과 템플릿 분석에는 [design-and-template.md](references/design-and-template.md)를 사용한다.

## 제작 흐름

1. 실제 사용 가능한 파일 읽기, PPT 렌더링, HTML 브라우저 확인, 파일 생성 기능을 확인한다.
2. 수업계획안·원고, 디자인 파일, 샘플 PPT를 실제로 열고 제작에 필요한 항목만 추출한다.
3. 장표별 제작 안내표가 없으면 해당 AI의 일반 추론으로 제작용 장표 초안을 만든다. 원문 내용을 평가하거나 임의 삭제하지 말고, 화면을 나눈 기준과 확인이 필요한 부분을 표시한다.
4. 결과 형식, 범위, 저장 위치, 파일명, 디자인 우선순위와 제작용 장표 초안을 한 번에 확인한다.
5. 서로 다른 유형의 대표 화면 2장을 먼저 만든다. 짧은 결과물이거나 사용자가 전체 제작을 바로 요청한 경우에는 범위에 맞게 조정한다.
6. 참고 화면과 대표 화면을 같은 표시 크기로 비교하고, 발견한 문제를 수정한 뒤 다시 렌더링한다.
7. 검증된 글자·간격·색·컴포넌트 규칙으로 요청 범위를 확장한다.
8. 최신 저장본을 다시 열거나 렌더링해 전체 화면을 확인한다.
9. 실제 결과 파일, 확인한 범위, 남은 제한만 짧게 보고한다.

HTML 제작이면 [html-deck.md](references/html-deck.md)를, PPTX 제작이면 [pptx-deck.md](references/pptx-deck.md)를 읽는다. 모든 제작의 마지막에는 [quality-check.md](references/quality-check.md)를 적용한다.

## 제작 원칙

- 사용자가 제공한 수업계획안과 원고를 임의로 평가·삭제하지 않는다. 화면 분할과 제목 정리는 제작용 초안으로 표시하고 사용자가 확인할 수 있게 한다.
- 화면에 맞지 않는 원고는 몰래 줄이지 말고, 문제가 되는 화면과 최소 수정안을 보여준다.
- 특정 프로젝트의 폴더명이나 영문 파일명을 강요하지 않는다.
- 사용자가 지정한 위치와 파일명을 사용한다. 미지정이면 이해하기 쉬운 한글 이름을 제안하고 파일 생성 전 확인한다.
- 같은 이름의 기존 파일을 발견하면 덮어쓰지 않는다.
- 요청받지 않은 홈페이지, 활동지, 수업계획서, 이미지 묶음, PDF를 추가로 만들지 않는다.
- 전체를 이미지 한 장으로 굳혀 편집 문제를 피하지 않는다. 편집 가능한 PPTX 요청에서는 글자, 표, 도형, 차트를 가능한 범위에서 편집 가능하게 유지한다.
- 디자인 파일의 수치를 맹목적으로 복사하지 않는다. 웹 UI용 작은 글자는 프로젝터용 교안 크기로 조정하고 그 이유를 남긴다.
- 화면 문장과 발표자용 설명을 분리한다. 원고에 발표노트가 없다면 새 내용을 지어내지 않는다.
- 실제로 열지 못한 자료는 확인했다고 말하지 않는다.
- 최신 파일을 다시 보지 못했으면 검증 완료라고 말하지 않는다.
- 제작 도구가 없으면 가능한 척하지 말고 만들 수 있는 형식과 필요한 대안을 알려준다.

## 완료 조건

- 요청한 형식과 범위의 실제 파일이 지정 위치에 있다.
- 디자인 파일의 핵심 규칙과 샘플 PPT에서 가져온 레이아웃 특성이 구분되어 적용되었다.
- 제목·본문·캡션의 위계, 여백, 정렬, 시각적 무게를 실제 렌더 화면에서 확인했다.
- 잘림, 겹침, 빈 화면, 깨진 글꼴, 잘못된 페이지 순서가 없다.
- HTML은 16:9 표시, 키보드 이동, 모션 축소 설정을 확인했다.
- PPTX는 화면 비율, 편집 가능 범위, 글꼴 대체, 전체 장표 렌더를 확인했다.
- 확인하지 못한 항목은 `미검증`으로 분명히 남겼다.

제3자 원칙의 출처와 배포 조건은 [third-party-notices.md](references/third-party-notices.md)를 따른다.
