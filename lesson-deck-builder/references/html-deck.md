# HTML 교안 제작

## 결과물의 성격

HTML 교안은 웹사이트 문서가 아니라 발표 화면이다. 화면마다 고정된 16:9 논리 캔버스를 사용하고, 브라우저 크기에 맞춰 비율을 유지한 채 확대·축소한다. 모바일용 문단 재배치와 발표 슬라이드 축소를 혼동하지 않는다.

## 캔버스

- 논리 크기는 `1600×900` 또는 `1920×1080` 중 하나를 정해 전체에서 유지한다.
- 화면 배율은 `min(viewportWidth / slideWidth, viewportHeight / slideHeight)` 방식으로 계산한다.
- 바깥 화면은 `100vw × 100dvh`를 사용하고 불필요한 스크롤을 막는다.
- 슬라이드는 중앙에 놓고 남는 영역은 별도 배경으로 처리한다.
- 브라우저 확대율 100%에서 1280×720, 1920×1080, 작은 노트북 화면을 확인한다.

## 구조와 편집성

- 각 화면을 독립된 `section` 또는 동등한 의미 구조로 만든다.
- 화면마다 식별자, 제목, 목적, 표시 내용, 발표노트, 모션, 출처를 추적할 수 있게 한다.
- 디자인 파일의 색·글자·간격은 CSS 변수 또는 한곳에서 관리되는 토큰으로 구현한다.
- 사용자가 원한 범위 안에서 HTML, CSS, JavaScript를 분리하거나 단일 파일로 묶는다.
- 외부 라이브러리는 꼭 필요한 경우에만 사용하며, 인터넷이 끊겼을 때의 동작을 알린다.

## 이동과 모션

- 이전·다음 이동은 키보드로 가능해야 한다.
- 현재 화면 번호와 전체 화면 수를 확인할 수 있게 한다.
- 모션은 설명 순서, 비교, 인과, 상태 변화, 조작 피드백 중 하나를 지원해야 한다.
- 필수 내용은 애니메이션이 없어도 이해할 수 있어야 한다.
- `prefers-reduced-motion`에서 움직임을 줄이거나 제거한다.
- 자동 재생으로 발표자의 통제권을 빼앗지 않는다.
- `transition: all` 대신 움직이는 속성을 명시하고 `transform`과 `opacity`를 우선한다.

## 발표와 출력

- 발표 화면에 대본 전체를 넣지 않는다.
- 발표노트가 제공되었다면 화면과 분리해 보거나 숨길 수 있게 한다.
- 인쇄 또는 PDF 출력이 요청되면 모든 필수 정보가 보이는 정적 상태와 페이지 나눔을 만든다.
- HTML 원본과 PDF·PPT 호환본을 같은 것으로 취급하지 않는다. 별도 형식은 사용자가 요청한 경우에만 만든다.

## HTML 검수

- 첫 화면과 마지막 화면이 정상적으로 열린다.
- 모든 화면을 키보드로 이동할 수 있다.
- 빠르게 여러 번 이동해도 상태가 꼬이지 않는다.
- 16:9 화면 안에서 글자와 이미지가 잘리거나 겹치지 않는다.
- 이미지와 글꼴 경로가 결과 폴더를 기준으로 작동한다.
- 브라우저 콘솔 오류와 깨진 링크가 없다.
- 모션 축소 환경에서도 내용과 이동을 사용할 수 있다.
- 최종 저장 후 브라우저를 새로 열어 다시 확인한다.
