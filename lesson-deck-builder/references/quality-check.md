# 교안 화면 검수

## 대표 화면 검수

대표 화면과 참고 장표를 같은 표시 크기로 본다. 개별 화면과 전체 축소 모음을 함께 확인한다.

| 확인 대상 | 실패 징후 | 수정 방향 |
| --- | --- | --- |
| 정보 위계 | 제목·배지·테두리만 강하고 핵심 설명이 약함 | 제목과 본문의 대비·굵기·크기를 다시 조정 |
| 문장 간격 | 한 문장의 두 줄이 서로 다른 항목처럼 떨어짐 | 줄 간격과 문단 앞뒤 간격을 구분 |
| 묶임과 여백 | 상자 크기는 맞지만 내용이 흩어져 보임 | 같은 의미는 가깝게, 다른 묶음은 더 멀게 배치 |
| 장식 비중 | 카드·그림자·배경 도형이 내용보다 먼저 보임 | 기능이 없는 장식을 줄이고 본문 대비를 높임 |
| 그래픽 역할 | 필요한 사례·도표 자리에 임시 도형만 있음 | 실제 자산을 사용하거나 주변 레이아웃을 다시 구성 |
| 글꼴과 단위 | 대체 글꼴 때문에 줄 수와 상자 비율이 바뀜 | 사용 가능한 글꼴과 출력 엔진에서 재검증 |

잘림이 없다는 이유만으로 통과시키지 않는다. 차이를 발견하면 원인을 적고 해당 요소만 수정한 뒤 다시 확인한다.

## 전체 확장 검수

- 확정 원고의 모든 화면과 순서가 결과에 있는지 확인한다.
- 검증된 디자인 규칙을 유지하되 내용 길이에 따라 레이아웃을 조정한다.
- 모든 화면을 같은 틀로 기계적으로 반복하지 않는다.
- 표지, 본문, 활동, 구간 전환, 마무리가 화면에서 구분된다.
- 화면에 제작 메모, 내부 경로, 프롬프트, API 키가 노출되지 않는다.
- 최종 검수에 사용한 화면이 최신 저장 파일에서 나온 것인지 확인한다.

## 완료 보고

결과 보고는 다음만 포함한다.

1. 만든 파일의 실제 위치와 형식
2. 완성한 장표 또는 화면 범위
3. 실제로 확인한 방법
4. 편집 가능 범위와 글꼴·모션의 제한
5. 사용자가 직접 볼 핵심 항목

확인하지 못한 항목은 통과했다고 추정하지 않는다. 기술적으로 만들 수 없는 요청은 가능한 척하지 않고 제한과 대안을 설명한다.
